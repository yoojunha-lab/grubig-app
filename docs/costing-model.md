# 원단 원가 모델 (Costing) — 2026-10 개편

원단 원가 계산 방식의 기획 의도·계산식·설정·데이터 구조를 정리한 문서입니다.
원가 관련 작업(원가 표, 원가 설정, 견적 기준원가, 설계서 원가)을 시작하기 전에 먼저 읽으세요.

---

## 1. 개편 배경 (대표님 요청, 2026-10-01)

| 항목 | 예전 방식 | 새 방식 |
|---|---|---|
| 편직비 | 1K/3K/5K 칸마다 kg당 편직료를 품목별로 직접 입력 | `max(난이도 정액, 생지 kg × kg단가)` — 택시 기본요금처럼 |
| 편직 LOSS | 1K/3K/5K 칸마다 % 직접 입력 | 오더 전체 **생지 kg 구간**으로 자동 (원가 설정) |
| 가공(염가공) LOSS | 1K/3K/5K 칸마다 % 직접 입력 | 품목의 **가공 유형**(일반·스판물·기모물…)으로 자동 (원가 설정) |
| 이화학검사 | 품목별 YD당 금액 | **컬러수(수량 구간) × 1컬러당 검사비** ÷ 수량 (원가 설정) |
| 운임 | 품목별 YD당 금액 | **수량 구간별 오더 총액** ÷ 수량 (원가 설정) |
| 외관검사 | 품목별 YD당 금액 | 전 품목 공통 YD당 단가 (원가 설정) |
| 계산 단위 | 1K/3K/5K 고정 3칸 | **수량을 넣는 함수** — 원가 표는 정해 둔 수량(§1-B: 300~5,000YD 6구간)을 넣어서 표시 |

목적: 수량이 늘었는데 편직비가 줄어들거나 갑자기 뛰는 구간이 없게 하고,
LOSS·검사·운임 기준을 한 곳(원가 설정)에서 관리해 전 품목에 일관되게 적용.

### 1-A. 수입 원사 운반비 (대표님 요청, 2026-10-02 추가)

| 항목 | 예전 방식 | 새 방식 |
|---|---|---|
| 원사 운반비 | 공급처마다 고정 원/kg (`freight`) | 국내 업체는 그대로. **수입사**는 **수입 국가별 kg 구간** 원/kg (원가 설정) |

- 원사 라이브러리 공급처 줄에서 **[수입] 체크 + 수입 국가** 선택 (기본 중국). 기존 수입사는 모두 중국으로 지정 (대표님 지정).
- 구간을 정하는 kg = **그 수입 원사만의 오더 투입 kg** (원사 투입 kg × 혼용률) — 대표님 확인.
  오더 전체 원사 kg로 하면 수입 원사가 일부만 들어가도 큰 구간이 잡혀 운반비가 낮게 계산되므로 쓰지 않음.
- 기본 구간 (중국, 대표님 지정): 300kg 미만 2,500원 / 300~1,000kg 2,000원 / 1,000~2,000kg 1,500원 / 2,000kg 이상 1,500원.
  이 구간만 **'N kg 미만' 규칙** (300kg 정확히 = 2,000원). 다른 원가 설정 구간은 'N 이하'.
- 수량 함수(`computeCostAtQty`) 안에서 계산 → 원가 표 1K/3K/5K는 물론, 나중에 만들 **임의 수량(야드수 입력) 판매가에도 자동 적용**.

### 1-B. 원가 표 6구간 + 염색 최소 청구 (대표님 요청, 2026-10-02 추가)

| 구간 (원가 표 ③) | 가정 | 염색비 | 이화학 |
|---|---|---|---|
| 300 · 500 · 800 YD (**2컬러 기준**) | 2컬러로 나눠 염색 | 컬러당 생지 kg가 **최소 청구 kg(기본 100kg) 미만이면 최소 kg로 청구** | 2컬러 |
| 1,000 · 3,000 · 5,000 YD (**MCQ 충족 기준**) | 컬러마다 MCQ를 맞춤 | 최소 청구 없음 (생지 kg 그대로) | 원가 설정 수량 구간 (2 / 4 / 6컬러) |

- 대표님 원문: "염색비는 100kg 이하 염색시 100kg로 청구". 염색은 컬러마다 따로 하므로 **컬러당** 적용.
- 100kg를 재는 기준은 **생지 kg** — 염가공료(§2)·MCQ(100kg ÷ (G/YD × (1 + 가공 LOSS%)))와 같은 기준 (§1-C 4번, 2026-10-03).
  처음(2026-10-02)에는 가공지 기준이었다가 바꿈.
- 100kg는 원가 설정 **④ 염색 최소 청구 (컬러당)** 에서 수정 (0이면 최소 청구 없음).
- 예) 면스판 립 300YD: 컬러당 150YD = 생지 55kg → 100kg로 청구 × 2컬러 = 200kg → 염가공비 YD당 3,252원 → 5,867원.
- **원단 목록·가설계서 판매가 시뮬레이션은 1K/3K/5K 그대로** (MCQ 충족 기준이라 최소 청구 없음 — 6구간 추가로 바뀐 값 없음).
  견적서는 2026-10-05부터 6구간 모두 (§5-B).

### 1-C. 원가 논리 검토 후속 결정 (대표님, 2026-10-03)

원가·견적 논리를 검토해서 나온 9가지에 대한 결정입니다.

| # | 내용 | 결정 | 반영 |
|---|---|---|---|
| 1 | YD당 정액이 통화가 바뀌어도 숫자 그대로 (₩300 → $300) | 환율로 환산 | 견적 시장 구분 전환, 가설계서 수출 보기 (§5) |
| 2 | 혼용률 합계가 100%가 아니어도 원가가 계산됨 | **저장 막기** + 그 밖의 문제는 '원가 확인 필요' 경고 | §4-B |
| 3 | 편직 LOSS·수입 운반비 구간 경계를 넘으면 총액이 줄어드는 지점 | 그대로 (수량이 많으면 싸지는 게 맞음) | 손대지 않음 (§7) |
| 4 | 염가공료는 가공지, MCQ는 생지 기준으로 서로 달랐음 | **염색소 청구는 생지 기준** (더 나올 수 있어 보수적으로) | 염가공비·염색 최소 청구 모두 생지 kg (§2) |
| 5 | 공통 환율을 바꾸면 열려 있는 견적 단가가 저절로 바뀜 | 견적 환율 고정, **[현재 원가로 다시 계산]** 버튼으로만 | §5 |
| 6 | 견적 복제 때 단가를 어떻게 할지 | 복제할 때 다시 계산할지 물어봄 | §5 |
| 7 | 1,000YD 미만 견적 | 대표님이 차례로 정리 예정 | 손대지 않음 |
| 8 | MCQ 미만 견적 | 나중에 견적서에 별도 시스템 | 손대지 않음 |
| 9 | 환율이 PC마다 따로 저장됨 | 회사 공통 환율 | §5-A |

## 2. 계산 순서 (오더 수량 Q YD)

오더 전체 금액으로 계산한 뒤 마지막에 ÷ Q 해서 YD당 원가를 만든다. 반올림은 최종 원가에서만.

| 단계 | 계산 | 비고 |
|---|---|---|
| 가공지 kg | Q × G/YD ÷ 1000 | G/YD = 생산 G/YD(입력값) 없으면 이론값 |
| 생지 kg | 가공지 kg × (1 + (가공 LOSS% + 후가공 LOSS%) ÷ 100) | 가공 LOSS = 품목 가공 유형의 % |
| 편직 LOSS% | 생지 kg가 속한 구간의 % | 'N kg 이하' 구간, 마지막은 '초과' |
| 원사 kg | 생지 kg × (1 + 편직 LOSS% ÷ 100) | 원사 투입량 |
| 재료비 | 원사 kg × 원사 단가(혼용 가중) + 수입 원사 운반비 | 내수=관세포함, 수출=관세제외 (운반비는 둘 다 포함) |
| 수입 원사 운반비 | 원사마다: 그 원사 kg(원사 kg × 혼용률) × 수입 국가 kg 구간 원/kg | 수입사 원사만. 국내 업체는 고정 원/kg가 원사 단가에 포함 (§1-A) |
| 편직비 | max(난이도 정액, 생지 kg × kg단가) | 정액 ÷ kg단가 지점부터 kg 계산 |
| 염가공비 | 청구 kg × 염가공료 | **생지 기준** (대표님 결정 2026-10-03 — 염색소는 생지를 받아 염색, 더 나올 수 있어 보수적으로). 컬러마다 따로 염색 → 컬러당 생지 kg가 최소 청구 kg 미만이면 최소 kg로 청구. 'MCQ 충족' 가정이면 최소 청구 없음 (§1-B) |
| 후가공비 | 가공지 kg × 후가공료 | 후가공 LOSS는 생지 kg에 반영 |
| 이화학검사 | 컬러수 × 1컬러당 검사비 | 오더 총액. 컬러수 = 구간 가정(2컬러 기준 → 2), 없으면 Q 구간 |
| 운임 | Q 구간의 금액 | 오더 총액 |
| 외관검사 | YD당 단가 × Q | |
| 품목별 추가비용 | YD당 금액 × Q | 품목마다 선택 입력 |
| **순원가/YD** | 위 합계 ÷ Q | 100원(내수)/센트(수출) 반올림 |
| **영업 기준원가/YD** | 순원가 × (1 + 위험마진%) | 위험마진은 예전과 동일 (terminology §1-A) |

예) 면스판 립 327g/yd · 스판물(13%) · 난이도 A(60만) · kg단가 2,000원 · 염가공료 8,800원
- 1,000YD: 생지 369.5kg × 2,000 = 739,020원 > 정액 → 739,020원 (YD당 739원)
- 500YD: 생지 184.8kg × 2,000 = 369,510원 < 정액 → 600,000원 (YD당 1,200원)
- 염가공비 1,000YD: 생지 369.5kg × 8,800 = YD당 3,252원 (가공지 기준일 때 2,878원 → 생지 기준 전환으로 가공 LOSS 13%만큼 오름)

### 편직 kg단가 구간 (품목별, 선택)
- 품목 화면 [kg단가 구간]으로 `1,000kg 이상 → 1,800원` 같은 구간 단가를 넣을 수 있다 (기본은 비어 있음).
- 생지 kg가 속한 구간의 단가를 **전체 kg에** 적용한다.
- 단, 구간이 바뀌며 단가가 내려가도 총액이 줄지 않게 **직전 구간 끝 금액**(다음 구간 시작 kg × 직전 단가)을 하한으로 둔다.
  예) 2,000원 → 1,000kg 이상 1,800원: 1,000~1,111kg 구간은 200만원 유지(화면 표시 '구간하한') → 이후 kg 계산.
- 원가 표 kg단가 칸 아래 '생지 ○kg 넘으면 kg 계산'은 구간까지 반영한 전환점 (구간마다 그 구간 단가로 정액을 넘는 첫 kg, 2026-10-06).

### 원가 표 칸 비우기 (2026-10-06)
- 숫자 칸(kg단가·염가공료·후가공·추가비용·kg단가 구간)은 **지울 수 있다** (예전엔 지우면 0이 강제로 들어가, kg단가가 0으로 저장되면 편직비가 정액만 잡혔음).
- kg단가 빈칸 = 기본값(예전 편직료 → 2,000원)으로 계산 — 칸 안에 그 단가가 흐리게, 칸 아래 '빈칸이라 기본 ○원'.
- 단가가 빈 kg단가 구간 줄은 계산에서 빠짐 (작성 중인 줄).
- 염가공료 빈칸 = 0원으로 계산 + '원가 확인 필요' 경고 (칸 안내는 '예: 8800'). 염색이 없는 원단은 0을 넣으면 경고가 사라짐.

### 구간(bracket) 공통 규칙
- 각 줄은 'N 이하' 경계값 + 값, 마지막 줄은 '직전 경계 초과'.
- 예) 편직 LOSS: 100kg 이하 10% / 300kg 이하 8% / 1,000kg 이하 5% / 1,000kg 초과 3%
  → 100kg 정확히 = 10%, 100.1kg = 8%.

## 3. 원가 설정 (전 품목 공통)

- 화면: 원단 관리 상단 **[⚙ 원가 설정]**, 원가 표 머리의 **[원가 설정]** 버튼 → `CostSettingsModal`
- 저장: Firestore `settings/general.costSettings` (통째로 교체, `updatedAt`·`updatedBy` 기록)
- 저장값이 없거나 일부 빠지면 `resolveCostSettings()`가 기본값으로 채움
- 사용 중인 편직 난이도·가공 유형은 삭제 불가 (원단·설계서·가설계서에서 쓰는 수를 셈. 값이 없는 옛 품목은 A·일반으로 셈)

| 설정 | 기본값 | 필드 |
|---|---|---|
| 편직 정액 | A 600,000원 (싱글 등 쉬운 아이템) / B 1,000,000원 (기계 손이 많이 가는 아이템) + 등급 추가 | `knitGrades[{id,name,fixedFee,desc}]` |
| 편직 LOSS | 100kg 이하 10% / 300kg 이하 8% / 1,000kg 이하 5% / 1,000kg 초과 3% | `knitLossBrackets[{max,pct}]` |
| 가공 LOSS | 일반 10% / 스판물 13% / 기모물 12% + 유형 추가 | `processTypes[{id,name,lossPct}]` |
| 이화학 | 1컬러당 200,000원 · 1,000YD 이하 2컬러 / 3,000YD 이하 4 / 5,000YD 이하 6 / 초과 6 | `chemTest{feePerColor,colorBrackets[{max,colors}]}` |
| 운임 | 500YD 이하 30만 / 1,000YD 이하 50만 / 3,000YD 이하 90만 / 5,000YD 이하 100만 / 초과 100만 | `freightBrackets[{max,amount}]` |
| 외관검사 | YD당 190원 | `visualInspectionPerYd` |
| 염색 최소 청구 (컬러당) | 100kg (생지 기준, 0이면 없음) — 2컬러 기준 구간에만 적용 | `dyeMinKgPerColor` |
| 수입 원사 운반비 | 중국: 300kg 미만 2,500 / 1,000kg 미만 2,000 / 2,000kg 미만 1,500 / 이상 1,500 (원/kg) + 국가 추가 | `importCountries[{id,name,brackets[{max,perKg}]}]` ('미만' 규칙) |

- 수입 국가는 원사에서 쓰는 중이면 삭제 불가 (원사 라이브러리의 수입 공급처 줄을 셈. 국가가 빈 줄은 중국으로 셈).
- 새 국가는 첫 번째 국가 구간을 복사해서 시작. 국가 구간이 비어 있으면 기본(중국) 구간으로 계산.
- 원사 라이브러리 상단 **[⚙ 수입 운반비]**(PC), 원사 수정 창의 **[구간 금액 수정]**으로 열면 ⑧ 수입 원사 운반비로 바로 스크롤.
- 원가 설정 화면 순서: ① 편직 정액 ② 편직 LOSS ③ 가공 LOSS ④ 염색 최소 청구 ⑤ 이화학 ⑥ 운임 ⑦ 외관검사 ⑧ 수입 원사 운반비 + 미리보기(원가 표 6구간).

기본값 출처: 대표님 지정(정액·가공 LOSS·편직 LOSS·이화학 컬러수) + 예전 원가에 맞춘 시작값(이화학 1컬러당·운임·외관검사).
설정에서 언제든 수정.

## 4. 품목(원단·설계서 costInput) 필드

| 필드 | 의미 | 기존 품목(값 없음)일 때 |
|---|---|---|
| `knitGrade` | 편직 난이도 id (A/B…) | `'A'` |
| `knitKgRate` | 편직 kg단가 (원/kg) | 예전 `knittingFee5k` → `knittingFee3k` → 2,000원 |
| `knitKgRateTiers` | 구간 단가 `[{fromKg, rate}]` | `[]` |
| `processType` | 가공 유형 id (normal/span/brushed…) | `'normal'`(일반) |
| `dyeingFee` | 염가공료 (원/kg, **생지 기준** — 2026-10-03부터) | 값은 그대로, 생지 kg에 곱함 → 염가공비가 가공 LOSS%만큼 오름 (저장된 견적은 그대로) |
| `finishing` | 후가공 `[{name, fee, lossPct}]` | 그대로 |
| `etcCosts` | 품목별 추가비용 `[{id, name, perYd}]` | 예전 기본 3항목(외관검사·이화학·운임, id `etc_visual/etc_chem/etc_freight`)은 **무시**(설정값 사용). 예전 사용자 항목은 3,000YD 값을 YD당으로 사용 |
| `riskMarginPct` | 위험마진 % | 그대로 |

- 기존 데이터는 **일괄 변환하지 않는다.** 계산할 때 위 규칙으로 읽고, 품목을 열어 저장하면 새 필드가 기록된다.
- 예전 필드(`knittingFee1k/3k/5k`, `losses`, `extraFee*`, `brandExtra`)는 지우지 않고 남겨둔다 — 계산에는 쓰지 않음.
- 원단 ↔ 설계서 양방향 동기화(`useFabric.handleSaveFabric`, `useDesignSheet.handleSaveSheet`)와
  아이템화 자동 등록·원단 불러오기·가설계서 불러오기 모두 새 필드를 같이 옮긴다.

### 4-A. 원사 공급처(`yarns/{id}.suppliers[]`) 필드 — 수입 원사 운반비

| 필드 | 의미 | 기존 원사(값 없음)일 때 |
|---|---|---|
| `freight` | 국내 업체 운반비 (원/kg, 고정) | 그대로. 수입사로 체크해도 **지우지 않고 보관** → 수입 해제 시 다시 사용 |
| `isImport` | 수입사 여부 ([수입] 체크) | `false`(국내) — 체크하기 전까지 원가는 예전과 같음 |
| `importCountry` | 수입 국가 id (`CN` = 중국 …) | 비었거나 삭제된 국가면 중국 → 첫 번째 국가로 계산 |

- 원사 단가는 **대표 공급처** 기준 (예전과 같음). 수입사 대표 공급처면 운반비 칸 대신 국가별 kg 구간.
- 원사 등록에서 업체를 고르면 라이브러리에 이미 있는 **같은 업체의 수입 지정을 따라감** (새 업체면 그대로).
- 기존 원사 일괄 지정: 원사 라이브러리 **[업체별 일괄변경]** → '수입사로 지정'(국가 선택) / '수입 해제' / '운반비 금액 변경'.
- 원사 엑셀 백업·등록 양식: `Import`(수입사면 Y) · `ImportCountry`(국가 이름, 비우면 중국) · `IsDefault`(기본 공급처면 Y) 열.
  예전 양식(두 열 없음)은 모두 국내로 등록.
- **원사 엑셀 업로드 = 등록 + 고치기** (2026-10-06): 같은 이름 원사가 라이브러리에 있으면 새로 만들지 않고 그 원사에
  공급처를 더하거나(새 업체) 값을 고침(같은 업체). 빈 칸은 그대로, 단가가 바뀌면 단가 이력 맨 앞에 오늘 날짜로 기록.
  기존 수입 공급처는 `Import` 칸이 비면 그대로, `N`이면 국내로. 나라만 적어도 수입사. → 원사 백업 파일을 고쳐 다시 올려도 중복이 생기지 않음.
  칸 읽기: 통화 ' usd'·'$' → USD, 관세 '8%'·% 서식, `Import` TRUE·O·예 (`utils/excelIO.js`). 모르는 통화·나라는 KRW·중국 + 안내.
- 원단 엑셀 업로드 (2026-10-06): 염가공료 0은 0 그대로(빈 칸만 기본 8,800원), '320g'·'2,000'·% 서식 혼용률도 읽음,
  0~100% 밖 혼용률이 있는 행은 등록하지 않음, 예전 백업의 '원사명 [업체]'도 원사를 찾음. 원단 백업은 원사 이름만 씀.
- 가설계서에서 단가를 직접 입력한 원사(`priceOverride`)는 관세·운반비 없이 그 단가 그대로 (예전과 같음).
- 화면 표시: 원사 목록은 운반비·내수 단가를 **범위**(예: ₩20,940~21,940)로, 원가 표 ①은 '+ 중국 운반비 (kg 구간)',
  ③ 구간별 표는 '└ 수입 원사 운반비' 줄에 수량마다 적용된 원/kg와 원사 kg.

### 4-B. 혼용률 100% 확인 + '원가 확인 필요' 경고 (대표님 결정, 2026-10-03)

**저장 막기** — 원사 혼용률 합계가 100%가 아니면 아래에서 저장·등록이 안 된다 (비율만큼 원가가 덜/더 잡혀 견적까지 틀어지므로).

| 어디서 | 막는 곳 |
|---|---|
| 원단 등록·수정 | 저장 버튼, 변경사항 확인 창의 '저장하고 나가기' (`CalculatorPage`, `FabricWorkspacePage`) |
| 설계서 | 설계서 저장, 아이템화 단계 전환, '설계서 내용으로 새 원단 등록' (`useDesignSheet`) |
| 가설계서 | 저장 (`useTempDesignSheet`) |
| 원단 엑셀 일괄 등록 | 그 행만 등록하지 않고, 끝나면 Article(합계%) 목록으로 알림 (`hooks/domains/useExcelIO.js` 업로드) |

- 합계는 소수 둘째 자리에서 반올림해서 본다 (`sumYarnRatio`) — 33.33 + 33.33 + 33.34 = 100 → 통과.
- 새 원단·설계서·가설계서는 첫 칸이 100%로 시작 → **원사를 아직 안 고른 초안도 저장은 됨** (아래 경고만 뜸).
- 이미 저장된 옛 데이터(합계 ≠ 100)는 그대로 두고, 열어서 고쳐야 저장된다. 원단 목록·견적에는 경고로 보임.

**'원가 확인 필요' 경고** — 저장은 되지만 원가가 덜 잡히거나 틀릴 수 있는 경우 (`calculateCostTiers().costWarnings`, 문구 배열)

| 사유 (화면 문구) | 언제 |
|---|---|
| 혼용률 합계 X% (100%가 아님) | 옛 데이터 등 |
| 원사를 고르지 않은 칸 (혼용률 X%) | 비율은 있는데 원사 선택이 빈 칸 → 그만큼 재료비 0 |
| 원사 라이브러리에 없는 원사: … | 라이브러리에서 지운 원사, 엑셀 등록 때 못 찾은 원사(`UNREGISTERED_…`) → 재료비 0 |
| 단가 0원 원사: … | 대표 공급처 단가가 비었거나 공급처가 없음 |
| 중량(G/YD) 0 | GSM·외폭·생산 G/YD가 비어 있음 |
| 염가공료가 비어 있음 (0원으로 계산) | 염가공료 칸을 비웠을 때 — 염색이 없으면 0을 넣음 (2026-10-06) |
| 원사 정보가 없음 (원가 0원) | 원사가 한 칸도 없는 원단 — 원사 없이 등록된 옛 데이터 등 (2026-10-06) |

- 보이는 곳: 원가 표 맨 위 빨간 안내(원단 등록·설계서·가설계서, 인쇄 제외), 원단 리스트 Article 옆 **'원가 확인' 배지**
  (마우스를 올리면 사유, 펼치면 사유 목록 — 모바일은 카드를 펼쳐서), 견적서 품목 Spec 옆 배지.
- 견적 품목: 넣을 때의 사유를 품목에 `costWarnings`로 저장 (기준원가와 같이 그 시점 값). 품목을 넣을 때 알림도 띄움.
  원단을 고쳐도 견적 배지는 그대로, **[현재 원가로 다시 계산]**을 누르면 새로 판단. 이 기능 전에 저장된 견적 품목은 배지 없음.
- 예전 '미등록 원사 ⚠️' · '혼용률 ❗️' 아이콘(원단 리스트)과 계산기 위 노란 '라이브러리에 없는 원사' 박스는 이 경고로 합침.
  내폭 > 외폭 🚨 아이콘은 원가와 무관해서 그대로.

## 5. 과거 견적·오더 보존

- **견적서**: 품목을 넣을 때의 영업 기준원가를 `basePrice{구간}`(300·500·800·1k·3k·5k)으로 품목에 저장. 목록·PDF·엑셀은 저장값만 사용
  → 원가 설정·계산식·공통 환율이 바뀌어도 저장된 견적 단가는 그대로. (견적서 구조는 §5-B)
- **견적 환율** (`quote.exchangeRate`, 2026-10-03): 견적마다 계산에 쓴 환율을 저장. 공통 환율(§5-A)을 바꿔도
  **열려 있는 견적·저장된 견적 모두 그대로** (예전엔 공통 환율을 바꾸면 열려 있는 견적이 저절로 다시 계산됐음 → 없앰).
  - 견적서 Rate 칸은 견적 환율을 보여주고, 공통 환율과 다르면 주황색 + '지금 환율 ₩X'.
  - 품목을 새로 넣으면 그 견적 환율로 계산 (한 견적 안 환율 통일).
- **[현재 원가로 다시 계산]** 버튼 (견적 품목 리스트 위): 확인 창(적용 환율 전 → 후)을 띄운 뒤 모든 품목을
  지금 원가(원가 설정·원사 단가) + 지금 공통 환율로 다시 계산하고 견적 환율도 바꾼다. 매출이익율·YD당 정액은 그대로.
- **시장 구분(내수 ↔ 수출) 전환**: 기준원가 통화·관세가 달라 다시 계산이 꼭 필요 → 확인 창 후 **견적 환율**로 다시 계산.
- **YD당 정액은 항상 원화로 적음** (`quote.marginAddCurrency = 'KRW'`, 대표님 요청 2026-10-05). 수출 견적은 판매가를 낼 때
  견적 환율로 나눠 $로 더함 (화면 칸 아래 '≈ $1.38'). 시장 구분을 바꿔도 정액 숫자는 그대로라 왕복해도 값이 변하지 않음.
  예전 수출 견적은 정액이 $로 적혀 있어(`marginAddCurrency` 없음 + 통화 USD) 그 값 그대로 씀 → 판매가 그대로.
  예전 수출 견적을 내수로 바꾸거나 [기본값으로]를 누르면 그때 원화로 바꿔 둠.
- 원단이 삭제된 품목은 다시 계산할 수 없어 그대로 둔다. 통화가 바뀔 때만 기준원가를 환율로 환산하고 '원가 확인 필요' 표시.
  원가 조각(§5-B)이 있으면 조각을 환산해서 기준원가를 다시 만듦 → 나중에 제외 버튼을 눌러도 값이 어긋나지 않음 (2026-10-06).
- **복제**: "현재 원가로 다시 계산할까요?"를 물어봄 → 예: 지금 원가·공통 환율 / 아니요: 원본 단가 그대로.
  작성자·작성일은 복제한 사람·지금으로.
- 아주 옛날 방식(추가 마크업 `extraMargin`) 견적은 시장 구분 전환·다시 계산을 막고 새 견적으로 작성하라고 안내 (`isNewMarginModel`).
  원단 추가(기준·별도 — 팝업·Article 입력·복붙·별도 견적으로 복사)도 막음 (2026-10-06: 더 넣으면 기존 품목 단가가 새 방식으로 바뀌어서).
- **가설계서 YD당 정액**(판매가 시뮬레이션): 원화로 입력·저장(`quoteMarginAdd`). 수출 보기에서도 원화로 입력하고,
  칸 아래에 공통 환율로 환산한 $를 보여 줌 (견적서와 같은 방식, 2026-10-05).
- **생산 오더 / PI**: 원가를 저장하지 않음 → 영향 없음.
- **원단 리스트·설계서·가설계서**: 열 때마다 공통 환율로 계산하는 화면이라 새 방식 숫자로 보임.

### 5-A. 공통 환율 (대표님 결정, 2026-10-03)

- 저장: Firestore `settings/general.exchangeRate = { value, updatedAt, updatedBy }` — 모든 직원이 같은 값을 씀.
  각 PC의 localStorage는 처음 열 때 쓰는 임시 값(캐시)일 뿐. 아직 공통 값이 없으면 각자 PC 값 → 누군가 한 번 저장하면 공통.
- 화면 위 환율 칸: 숫자를 입력하고 **Enter 또는 칸 밖 클릭** → "공통 환율을 ₩A → ₩B로 바꿉니다…" 확인 창 → 저장.
  Esc는 취소. 마우스를 올리면 마지막 변경(누가·언제). 공통 값이 아직 없으면 주황 점. (예전엔 한 글자 칠 때마다 바로 바뀌었음)
- 공통 값이 아직 없으면 **지금 보이는 값을 그대로 다시 쳐도** "지금 환율 ₩X을 회사 공통 환율로 저장합니다" 확인 후 저장 (2026-10-06,
  예전엔 같은 값이면 무시돼서 지금 값을 공통으로 올릴 방법이 없었음). 공통 값이 있으면 같은 값은 그냥 무시.
- 저장에 실패하면 원래 값으로 되돌림. DEV 미리보기(로그인 우회)에서는 저장 없이 화면에서만 바뀜.

### 5-B. 견적서 — 기준 견적 / 별도 견적 (대표님 요청, 2026-10-05)

| 칸 | 무엇 | 바이어 견적서 |
|---|---|---|
| **기준 견적** (`quote.items`) | 원가 표와 같은 6구간(300·500·800YD 2컬러 기준 / 1,000·3,000·5,000YD MCQ 충족 기준) 단가 | **기준 견적서** PDF·엑셀 — '견적서 표시' 체크한 구간만 (`quote.shownTiers`) |
| **별도 견적** (`quote.customItems`) | 원단마다 수량·컬러수·제외 항목을 넣어 원가부터 다시 계산 (예: 300YD 3컬러) | **별도 견적서** PDF·엑셀 — 줄마다 '견적서' 체크한 줄만 (`row.show`) |

- 두 견적서는 **따로 출력해서 따로 보냄** (견적서 화면 칸 머리줄, 견적 목록의 PDF·Excel / 별도 PDF·별도 버튼).
- **표시 구간 기본값**: 500·800·1,000·3,000YD (대표님 지정). 1개 이상은 켜 둬야 함. 예전 견적(저장값 없음)은 1,000·3,000·5,000YD.
- **기본 마진** (대표님 지정, `constants/quote.js` — 같은 날 800YD를 23% · 1,500원으로 조정):

  | | 300 | 500 | 800 | 1,000 | 3,000 | 5,000 |
  |---|---|---|---|---|---|---|
  | 매출이익율 | 25% | 25% | 23% | 20% | 20% | 20% |
  | YD당 정액 (원) | 2,000 | 2,000 | 1,500 | 1,000 | 800 | 500 |

  정액은 원화로 적고, 수출 견적은 판매가를 낼 때 견적 환율로 나눔 (환율 1,450 → $1.38 / 1.38 / 1.03 / 0.69 / 0.55 / 0.34). [기본값으로] 버튼으로 되돌림.
- **외관검사·시험성적서(이화학) 제외**: 칸마다 **전체에 적용하는 버튼** — '기준 견적 전체'(`excludeVisual`/`excludeChem`),
  '별도 견적 전체'(`customExcludeVisual`/`customExcludeChem`). 처음엔 별도 견적을 줄마다 체크했으나 대표님 요청으로 칸 전체로 바꿈.
  - 품목에 원가 조각(`costParts[구간] = { raw, chem, visual }`: 반올림·위험마진 전 YD당 순원가와 그중 이화학·외관검사 몫, 견적 통화)과
    `riskPct`를 같이 저장 → 체크를 바꾸면 `기준원가 = 반올림((raw − 뺄 항목) × (1 + 위험마진%))`로 그 항목만 빼고 넣음 (다른 원가는 그대로).
  - 아무것도 안 빼면 원가 표의 영업 기준원가와 같은 값 (2026-10-05 샘플 72개 대조 일치).
  - 원가 조각이 없는 예전 품목(별도 견적은 원가 조각 없는 줄)이 하나라도 있으면 버튼이 바뀌지 않고
    [현재 원가로 다시 계산]을 먼저 하라고 알림 (2026-10-06 — 예전엔 단가는 그대로인데 견적서에 'NOT INCLUDED'만 찍힐 수 있었음).
  - 바이어 견적서 약관에 'VISUAL INSPECTION NOT INCLUDED' / 'TEST REPORT NOT INCLUDED' (기준·별도 각각의 버튼 기준).
- **별도 견적 계산**: `computeCostAtQty(원단, 수량, 견적 환율, { colors })` — 이화학은 컬러수만큼, 컬러당 생지가 최소 청구 kg
  미만이면 염색 최소 청구가 자동으로 붙음. 화면에 컬러당 수량·'MCQ 미달'·'염색 최소 청구 포함'·총액(판가 × 수량, 화면만).
  - 이익율을 비워 두면 수량이 속한 기준 구간의 견적 일괄값 (그 수량 이하 중 가장 큰 구간, 300YD 미만은 300YD 구간).
    YD당 정액은 비워 두면 0 (별도 견적은 정액 기본값 없음 — 대표님 지정 2026-10-05).
  - 수량·컬러를 바꾸면 그 줄만 견적 환율로 다시 계산. 원단이 삭제된 줄은 수량·컬러를 바꿀 수 없음.
  - **원단 추가는 기준 견적과 같은 방식**: [원단 검색·추가] 팝업(이미 담긴 원단은 '추가됨'), 표 아래 Article 입력(Enter)·엑셀 세로 복붙,
    기준 견적에서 체크 → [별도 견적으로 복사]. 300YD · 2컬러로 시작. **같은 원단은 한 줄만** (조건은 그 줄의 수량·컬러를 바꿈).
- **바이어 견적서 문구** (영문): 원화 = 'PRICE IN KRW · VAT EXCLUDED' + 'VAT EXCLUDED', 수출 = 'FOB PRICE'.
  기준: 'PRICES ARE PER YARD, BASED ON TOTAL ORDER QUANTITY', '{300~800 중 표시 구간} YD: UP TO 2 COLORS (SMALL-LOT DYEING CHARGE INCLUDED)',
  '{1,000 이상 표시 구간} YD: MCQ PER COLOR REQUIRED' + 기존 약관. 별도: 'PRICES APPLY ONLY TO THE QUANTITY (TOTAL PER ORDER) AND NUMBER OF COLORS STATED'.
  문구는 `quoteModel.buildQuoteTerms(quote, kind)` · `quotePriceBasis(currency)` 한 곳에서 만들어 PDF·엑셀이 같이 씀.
- **예전 견적 호환** (`normalizeQuote`): 판가는 그대로. 새 구간(300·500·800)의 이익율·정액은 기본값으로 채움(0% 방지),
  새 구간을 켜면 단가 '—' + [현재 원가로 다시 계산] 안내. 아주 옛날(extraMargin) 견적은 구간 설정·별도 견적을 막음.
- 시장 구분 전환·[현재 원가로 다시 계산]·복제 때 별도 견적 줄도 같이 다시 계산 (줄에 직접 넣은 정액은 같은 환율로 환산).
- 저장: 기준 견적이나 별도 견적 중 하나만 있어도 저장. 기준 견적은 Article 순 정렬, 별도 견적은 넣은 순서 그대로.
- **출력 전 확인** (2026-10-06, `quoteModel.validateQuoteForExport(quote, kind)` → `{ errors, warnings }`): PDF·엑셀 버튼을 누르면 먼저 확인.
  - 막음(알림): 바이어 이름 없음 / 기준 견적 품목 없음 / 표시 구간에 단가가 없는 칸(예전 품목 — [현재 원가로 다시 계산] 또는 그 구간 표시 끄기)
    / 별도 견적서에 넣을 줄 없음 / 수량·컬러가 비었거나 원가가 없는 별도 줄.
  - 물어봄(확인 창): '원가 확인 필요' 품목·줄이 있을 때 — 그래도 만들지 선택.
- 입력 칸(매출이익율·YD당 정액·품목 이익율): 지우고 새로 칠 수 있음, 비운 채로 칸을 떠나면 원래 값 (2026-10-06).
- 복제·새 견적은 한 번도 저장 안 했고 품목이 있으면 나갈 때 '저장할까요?' (예전엔 복제본이 묻지 않고 사라졌음).
- 견적 목록에서 **지금 열려 있는 견적을 다시 누르면 아무 일도 없음** (2026-10-06 — 예전엔 저장 전 내용으로 다시 불러와 고친 내용이 사라지고,
  다음 저장 때 옛 내용으로 덮어쓸 수 있었음).

## 7. 확장 포인트 / 남은 과제

- **임의 수량 칸**: 원가 표에 수량 입력 칸만 추가하고 `calculateCostAtQty(fabric, qty, null, { colors, assumeMcq })`(useFabric) 또는
  `computeCostAtQty(fabric, qty, ctx, opts)`를 부르면 바로 계산된다. (예: 15,000YD)
  opts를 비우면 컬러수 = 이화학 수량 구간, 염색 최소 청구 적용. 컬러수 입력 칸·'MCQ 맞춤' 체크를 같이 두면 그대로 넘기면 됨.
  수입 원사 운반비도 이 함수 안에서 그 수량의 원사 kg로 구간을 고르므로 따로 손댈 것 없음 (결과 `importFreight.lines`).
- **원가 표 구간 바꾸기**: `COST_DISPLAY_TIERS`(수량·묶음·컬러수·MCQ 가정)만 고치면 표·설정 미리보기가 같이 바뀜.
  같은 묶음끼리는 붙여 둘 것. `tier1k/3k/5k` key는 견적·원단 목록이 읽으므로 없애지 말 것.
- **같은 수입사 원사 kg 합산**: 지금은 원사마다 따로 구간을 정한다. 한 원단에 같은 수입사 원사가 2개 이상 들어가
  한 번에 실어 오는 경우 kg를 합쳐 구간을 정하려면 `costAtQty`의 `lineFreight`를 공급처별로 묶으면 된다 (대표님 결정 필요).
- **구간 경계 계단 (그대로 두기로 함)**: 편직 LOSS 구간(생지 kg)·수입 운반비 구간(원사 kg) 경계를 넘으면
  오더 총액이 오히려 줄어드는 지점이 있다 (검토 때 편직 LOSS 경계에서 최대 약 40만원, 수입 운반비 경계에서 약 49만원).
  대표님 결정(§1-C 3번): 수량이 많으면 싸지는 게 맞아서 그대로. 편직비 kg단가 구간만 '구간하한'으로 막혀 있음.
  나중에 막으려면 편직비처럼 '직전 구간 끝 금액'을 하한으로 두면 된다.
- **1,000YD 미만 · MCQ 미만 견적** → 2026-10-05 견적서 개편으로 해결 (§5-B): 기준 견적 300·500·800YD 구간 + 별도 견적(수량·컬러 입력).
- 설계서 변경 이력에는 가공 유형이 id(`span` 등)로 남는다 — 화면 표시 개선 여지.
