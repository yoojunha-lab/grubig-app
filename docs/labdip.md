# LAB-DIP (생산 ▾ LAB-DIP) — 기획 · 구현

> 대표님 요청 2026-10-27. 예전 **영업 ▾ Lab-Dip 발송**(바이어 시트 인쇄 + 발송 기록, 2026-08-12)을 **생산 ▾ LAB-DIP**으로 옮기고,
> 공장에 L/D를 의뢰하는 일과 바이어에게 보내는 일을 한 화면에 묶음. 관련 용어는 `docs/terminology.md` §2-L.

---

## 1. 요청 내용 (대표님, 2026-10-27)

1. 공장에 L/D를 **의뢰**하는 기능 + 바이어에게 **발송**하는 기능을 묶기. 의뢰할 때 원단 리스트에서 **ARTICLE · Item Name(혼용률)** 가져오기.
   Wool이 슈퍼워시인지 레귤러인지 Item Name에 없어서 **고르는 칸** — 원사 이름에 **SW**가 있으면 슈퍼워시로 **자동 체크**(아니면 담당자가 풂) + 원사 이름을 보고 코멘트. **GSM · 폭**도 가져와 적기.
2. L/D NO.는 **GB26001**부터 (26년 001번). 27년이 되면 **GB27001**부터 다시. **26년은 22번까지 썼음**.
3. EZ-TEX에서도 L/D 의뢰를 함 → 그럴 때는 **바이어 발송만** 하는 기능.
4. **진행중 · 컨펌대기중 · 완료**로 나눠 납기 · 진행 상황 관리.
5. 의뢰하는 **공장을 고름**. 바이어에게 보낼 때는 **공장을 밝히지 않음**.
6. 공장 의뢰서는 L/D 번호 없이 **컬러명 + PANTONE**(특이사항), 또는 바이어에게 받은 **스와치를 붙여** 보냄 → 공장에서 번호를 붙여 오면 바이어 시트를 만들어 보냄(지금처럼).

## 2. 정한 것

| 질문 | 대표님 답 (2026-10-27) |
|---|---|
| GB 번호는 무엇마다? | **의뢰 한 건마다** (아티클 하나 + 컬러 여러 개). 컬러 번호(25S038 "A")는 지금처럼 **공장 번호**. 바이어 시트 머리에 L/D NO. |
| EZ-TEX 건도 GB 번호? | **붙임** (모든 L/D가 한 번호 줄). EZ-TEX 번호는 따로 적는 칸 |
| 공장 의뢰서에 바이어 이름? | **늘 안 적음** (STYLE도 안 찍음 — 바이어 스타일 번호라서) |
| 일부 컬러만 리젝되면? | **같은 번호에 2차로** — 그 컬러만 2차 의뢰, 바이어 코멘트가 2차 의뢰서에 찍힘 |

같이 넣은 것 (추천 — 브리핑에서 OK): 광원 체크(D65 · TL84 · CWF · A) · 컨펌한 낱장 기록 · 리젝 코멘트 → 2차 의뢰서 · 공장 의뢰서에 담당자 이름.
기본값 (바꿀 수 있음): 메뉴 위치 생산 현황 바로 아래 · 낱장 수 기본 2 · 컨펌대기 7일 넘으면 노랑 · 예전 기록은 '완료'.

## 3. 흐름

```
[+ 새 L/D ▾]
 ├─ 공장에 의뢰 ─────────────── 저장 → L/D NO. → [공장 의뢰서] 인쇄 → 공장으로
 └─ 바이어 발송만 (EZ-TEX 의뢰) ── 의뢰서 단계 없음 (공장 의뢰는 EZ-TEX에서)
        ▼  진행중 — 공장 진행중 (공장 납기 D-day · N일 지남)
   [L/D 도착] 컬러마다 공장 번호(25S038) · 낱장 수 → L/D 도착 (발송 전)
        ▼  [바이어 발송] 보낼 컬러 체크 → 바이어 시트 PDF + 발송일 · 방법
        ▼  컨펌대기중 — 보낸 지 N일 (7일 넘으면 노랑)
   [결과 넣기] 컬러마다: 컨펌(A·B·C 중 고르기) / 리젝(코멘트) / Drop
        │                      └→ [2차 의뢰] 같은 L/D NO. → 다시 공장 진행중
        ▼  완료 — 모든 컬러가 컨펌 또는 Drop
```

- **상태는 컬러마다** — 한 의뢰에 5컬러 중 3개 컨펌 · 1개 리젝 · 1개 회신 대기처럼 섞이는 게 보통이라서.
- 진행 버튼(도착 · 발송 · 결과 · 2차 의뢰 · Drop · 되돌리기)은 **누르면 바로 저장** (그때 고쳐 둔 다른 칸도 같이). 나머지 칸은 [저장].
- 공장에서 일부만 먼저 와도 온 것부터 보낼 수 있음. EZ-TEX 건은 컬러 칸 '공장 번호'에 바로 적어도 'L/D 도착'이 됨.

## 4. L/D NO. — `labdipModel.nextLdNo`

- **GB + 의뢰일 연도 2자리 + 3자리** (GB26023). **저장할 때 붙음** — 작성하다 안 저장하면 번호를 안 써서 비는 번호가 없음.
- 그해 쓴 번호 중 가장 큰 번호 + 1. **26년은 이 화면 밖에서 22번까지 썼음** → `LD_NO_USED_BEFORE = { 26: 22 }` → GB26023부터. 다른 해는 001부터.
- 번호 칸은 고칠 수 있음 (그사이 손으로 쓴 번호가 있으면 첫 의뢰에서 고치면 다음부터 이어짐). **같은 번호는 저장 막음** (칸 아래 빨간 글자 + 알림).
- 저장돼 있던 번호를 칸에서 지우고 저장하면 원래 번호 그대로. 예전 기록은 번호를 직접 넣을 때만 붙음.
- **두 PC가 동시에 새 L/D를 저장해도 번호가 안 겹침** (2026-10-27 검토): 새 L/D는 문서 id를 번호로 만들어(`ldDocId` → `labdip_GB26028`) 저장소에 '없을 때만 만들기'(`db.createDocument` 트랜잭션). 방금 다른 곳에서 그 번호를 썼으면 다음 번호로 저장하고 알림, 직접 넣은 번호면 저장을 멈추고 알림.
- 지운 L/D가 그해 가장 큰 번호였으면 그 번호는 다시 쓰임 → **그만둔 의뢰는 지우지 말고 [남은 컬러 모두 Drop]** (지우기는 잘못 만든 것만).

## 5. 상태 · 탭 · 납기 — `colorStage`, `labdipTabKeys`, `labdipTiming`

| 컬러 단계 | 뜻 | 탭 | 색 |
|---|---|---|---|
| 공장 진행중 | 의뢰함, L/D 아직 안 옴 | 진행중 | 파랑 |
| L/D 도착 | 공장 번호 받음, 바이어에게 아직 안 보냄 | 진행중 | 남색 |
| 리젝 | 바이어 리젝, 다음 차수 의뢰 전 | 진행중 | 빨강 |
| 컨펌대기 | 바이어에게 보냄, 결과 기다림 | 컨펌대기중 | 노랑 |
| 컨펌 "B" | 컨펌 (어느 낱장인지) | 완료 | 회색 |
| Drop | 바이어가 그 컬러를 안 하기로 | 완료 | 회색 점선 |
| 예전 기록 | 예전 Lab-Dip 발송 기록 (완료로 보관) | 완료 | 회색 |

- 의뢰 줄은 끝나지 않은 컬러의 탭에 모두 나옴 (섞이면 진행중 · 컨펌대기중 둘 다) — 그 탭 단계가 아닌 컬러 칩은 흐리게. **완료 탭은 모든 컬러가 컨펌 · Drop일 때만**.
- 납기: **공장 납기**(1차는 의뢰 머리 칸, 2차부터는 차수마다) · **바이어 납기**(선택 — 아직 안 보낸 컬러가 있을 때만 보임). 'D-3' · 'D-day' · **'N일 지남'**(빨강), 2일 이내 노랑.
- 줄 순서: 진행중 = 납기 급한 순 / 컨펌대기중 = 오래 기다린 순 / 완료 = 최근에 끝난 순.

## 6. 원단 · 울 종류 · 광원

- [원단 관리에서 고르기] → ARTICLE · ITEM NAME · GSM · 내폭 · 외폭을 **고를 때 복사** (의뢰서에 적은 값이 그대로 남게 — 고칠 수 있음). 원단 관리에 아직 없는 개발 원단은 직접 입력.
- **울 종류** (`detectWoolType`): ① 원사 이름에 **SW**(또는 SUPER WASH) → 슈퍼워시 + "원사 'F/60Nm SW/N 87/13'에 SW가 있어 슈퍼워시로 체크했어요"
  ② ITEM NAME에 SW → 슈퍼워시 ③ 울 원사(분류 소모 · 방모, 이름 WOOL · MERINO)인데 SW 없음 → 레귤러 울 ④ ITEM NAME에 울(W/…)만 → 레귤러 울 ⑤ 울이 없으면 울 없음.
  담당자가 바꾸면 그 뒤로는 자동으로 안 바꿈 ('담당자가 바꿨어요 — 자동으로는 …' + [자동 값으로]). SWIM · 2W처럼 붙은 글자는 SW · W로 안 봄.
- **광원** D65 · TL84 · CWF · A 체크 — 공장 의뢰서에 찍힘.

- [공장 의뢰서] = 지금 **공장 진행중인 컬러** (없으면 Drop 안 한 컬러 모두 — 다시 인쇄). 새 L/D이거나 저장 안 한 변경이 있으면 먼저 저장(번호가 저장소에 있게).

- 바이어 시트: [바이어 발송] 창에서 체크한 컬러만, DATE = 발송일.
- **[바이어 시트] 다시 인쇄** (작성 화면 머리, 2026-10-27 검토): 공장 번호가 있는 컬러 모두(보낸 · 컨펌 · 예전 기록 — Drop 빼고), DATE = 그중 가장 늦은 발송일. 발송 기록은 안 바뀜 (`buyerReprint`).
